# بستهٔ تحویل برندیار

## محصول

برندیار یک SaaS فارسی و راست‌چین برای مدرس‌ها، مربی‌ها و تولیدکنندگان محتوای آموزشی اینستاگرام است. هدف محصول کمک به تحلیل برند شخصی، تعیین مسیر رشد، ایده‌پردازی محتوا، نگارش/بهبود سناریو، کتابخانه محتوا و تقویم انتشار است.

## وضعیت فعلی

- سایت عمومی و پیش‌نمایش داشبورد در `index.html` به‌صورت مستقل قابل نمایش است. CSS و JavaScript آن در همان فایل درون‌گذاری شده‌اند.
- `styles.css` و `app.js` نسخه‌های جداگانهٔ همان ظاهر و رفتار هستند؛ تغییر هرکدام باید در نسخهٔ درون‌گذاری‌شدهٔ `index.html` نیز همگام شود.
- داده‌های بخش کاربر نمونه‌اند. بخشی از وضعیت پیش‌نمایش، با رضایت کاربر، در `localStorage` مرورگر ذخیره می‌شود؛ این داده‌ها دادهٔ واقعی سرویس نیستند.
- پنل کارکنان در فایل‌های `admin.html`، `admin-panel.js`، `admin-panel.css` و `admin-client.js` قرار دارد. هیچ لینک عمومی به آن وجود ندارد.
- `server.py` یک MVP محلی برای احراز هویت کارکنان، MFA مبتنی بر TOTP، نشست، محدودسازی تلاش ورود، خروج، پاسخ‌های امنیتی و دادهٔ خواندنی CRM/تیکت است. هنوز عملیات نوشتنی، پرداخت، اتصال رسمی اینستاگرام، هوش مصنوعی و حساب واقعی کاربران را پیاده نمی‌کند.
- بک‌اند عمداً در GitHub قرار ندارد و در `.gitignore` نادیده گرفته می‌شود. این بسته آن را شامل می‌شود.

## فایل‌ها

| فایل | کاربرد |
| --- | --- |
| `index.html` | فایل مستقل سایت، شامل HTML/CSS/JS برای نمایش مستقیم |
| `styles.css` | CSS نسخهٔ جداگانهٔ سایت |
| `app.js` | منطق مسیرها و تعامل‌های سایت و داشبورد |
| `admin.html` | صفحهٔ HTML پوستهٔ پنل کارکنان |
| `admin-panel.js` | رابط نقش‌محور مدیریت با تابع `mountAdmin` |
| `admin-panel.css` | سبک RTL و واکنش‌گرای پنل |
| `admin-client.js` | اتصال محافظت‌شدهٔ پنل به API |
| `server.py` | MVP بک‌اند محلی با Python استاندارد و SQLite |
| `admin-architecture.md` | طراحی کامل مجوزها، امنیت، API، مدل داده و مسیر توسعه |
| `.gitignore` | جلوگیری از ثبت پایگاه داده و بک‌اند محلی در GitHub |

## اجرای سایت عمومی

برای نمایش فقط رابط عمومی، فایل `index.html` را با یک وب‌سرور فایل ایستا نمایش دهید. این حالت هیچ ورود واقعی، پرداخت یا اتصال خارجی ندارد.

## اجرای MVP کارکنان

نیازمندی: Python 3.11 یا جدیدتر. پکیج خارجی لازم نیست.

1. یک کلید TOTP در برنامهٔ Authenticator بسازید و مقدار Base32 آن را نزد مدیر نگه دارید.
2. حساب کارکنان را ایجاد کنید:

   ```bash
   python server.py add-staff staff@example.com "نام همکار" owner
   ```

   نقش‌های مجاز: `owner`، `product`، `support`، `finance` و `viewer`.

   این فرمان رمز عبور حداقل ۱۲ کاراکتری و کلید Base32 برنامهٔ Authenticator را به‌صورت تعاملی می‌پرسد. این مقادیر را هرگز در کد، خط فرمان، Git، فایل متنی یا مرورگر ثبت نکنید.

3. سرویس را اجرا کنید:

   ```bash
   python server.py serve --port 8000
   ```

4. برای استفادهٔ واقعی، سرویس باید فقط پشت یک پراکسی HTTPS قابل‌اعتماد منتشر شود. کوکی نشست `Secure` است و روی HTTP واقعی مرورگر ارسال نمی‌شود. مسیر `/admin` تنها بعد از ورود و MFA در دسترس است.

پایگاه داده به‌صورت پیش‌فرض در `.data/brandyar.sqlite3` ایجاد می‌شود. برای محیط عملیاتی، مسیر آن را با متغیر محیطی `BRANDYAR_DB` به فضای خصوصی و دارای پشتیبان‌گیری منتقل کنید.

## مرزهای امنیتی مهم

- نقش دریافتی در مرورگر مرز امنیتی نیست. تمام دسترسی‌ها باید در سرور برای هر درخواست بررسی شوند.
- پنل مدیریت و فایل‌های آن نباید بدون نشست تأییدشده پاسخ داده شوند.
- دادهٔ حساس، رمز، توکن OAuth، اطلاعات کارت، کوکی و کلید API نباید به HTML، JavaScript عمومی، پاسخ API، لاگ یا Git وارد شود.
- عملیات حساس مانند بازپرداخت، تغییر پلن، لغو نشست، تغییر محتوا و دسترسی پشتیبانی به دادهٔ کاربر باید دلیل، CSRF، MFA متناسب، کنترل نسخه، تأیید مرحله‌ای و audit append-only داشته باشند.
- اتصال اینستاگرام فقط با OAuth رسمی انجام شود؛ هرگز رمز اینستاگرام را دریافت نکنید.
- قبل از انتشار واقعی، احراز هویت و مجوزها باید با تست‌های یکپارچه و بررسی مستقل امنیتی ارزیابی شوند.

## پیشنهاد دقیق برای ادامهٔ توسعه

1. **استقرار:** پراکسی HTTPS، فرایند سرویس پایدار، ذخیره‌سازی پایگاه داده خارج از فایل‌های عمومی، بکاپ، لاگ ساخت‌یافته و مانیتورینگ اضافه شود.
2. **دادهٔ واقعی:** مدل‌های `users`، پروفایل برند، مصرف، اشتراک، تیکت و timeline از `admin-architecture.md` کامل شوند؛ pagination و پالایش نقش‌محور پیاده شود.
3. **عملیات مدیریت:** APIهای mutation را یک‌به‌یک با مجوز سرور، CSRF، idempotency key، `expected_version`، دلیل اجباری و ثبت audit تراکنشی بسازید. تا تکمیل این موارد، دکمه‌های تغییر پنل فعال نشوند.
4. **حساب کاربران:** ثبت‌نام، بازیابی رمز و نشست کاربران عادی باید جدا از کارکنان طراحی شود. کاربر عادی هیچ مسیر یا دادهٔ مدیریت دریافت نکند.
5. **مالی و OAuth:** پرداخت را فقط از طریق درگاه رسمی و بدون ذخیرهٔ اطلاعات کارت پیاده کنید. OAuth اینستاگرام و کلیدهای سرویس هوش مصنوعی فقط در secret store سمت‌سرور نگهداری شوند.
6. **تست:** سناریوهای بدون نشست، نقش مشاهده‌گر، پشتیبانی، مالی، MFA نامعتبر، CSRF نامعتبر، درخواست تکراری، نسخهٔ متعارض و خروج را تست کنید. رابط را برای RTL، موبایل، کیبورد، کنتراست و کاهش حرکت بررسی کنید.

## دستور پیشنهادی برای هوش مصنوعی بعدی

«این پروژهٔ برندیار یک SaaS فارسی RTL برای مدرس‌ها و تولیدکنندگان محتوای آموزشی است. ابتدا `HANDOFF.md` و سپس `admin-architecture.md` را کامل بخوان. سایت فعلی در `index.html` مستقل است و `app.js`/`styles.css` نسخه‌های جداگانهٔ آن هستند؛ هر تغییری را بین آن‌ها همگام نگه دار. بک‌اند محلی در `server.py` است و هنوز MVP خواندنی کارکنان محسوب می‌شود. هیچ لینک عمومی مدیریت نساز، نقش مرورگر را معتبر فرض نکن، عملیات حساس را بدون مجوز سمت‌سرور، MFA، CSRF، دلیل، کنترل نسخه، ثبت audit و پاسخ قطعی فعال نکن. رازها و داده‌های حساس را در کد، Git، HTML یا log ثبت نکن. ابتدا تغییر کوچک و تست‌شده انجام بده و سپس مرحله‌ای توسعه را ادامه بده.»
