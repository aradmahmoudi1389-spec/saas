# قرارداد معماری حساب و محصول برندیـار

## مرز صفحات

- `/account`: اطلاعات پایه، تصویر PNG/JPEG کوچک، اطلاعات تماس تأییدنشده، خروج و کارت دسترسی محصول. فاقد ابزار برند و خروجی محتواست.
- `/brandyar/dashboard`: اتاق فرمان برند، اقدام بعدی، وضعیت هفت مرحله و خروجی‌های واقعی اخیر.
- `/brandyar/roadmap`: هدف، ورودی، خروجی، وضعیت و اقدام هر مرحله؛ سه مرحلهٔ اول خلاصهٔ قابل‌استفاده از اطلاعات ثبت‌شده دارند.
- `/brandyar/identity`: هویت حرفه‌ای و مرور/تأیید آن.
- `/brandyar/guide`: صدای برند؛ `/brandyar/pillars`: ستون‌های محتوایی.
- `/brandyar/create`: کارگاه؛ `/brandyar/library`: کتابخانه؛ `/brandyar/calendar`: برنامه‌ریزی دستی انتشار.
- `/brandyar/settings`: ترجیحات محصول و دسترسی؛ مستقل از حساب.
- `/personal-brand`: تست و نتیجهٔ مستقل. مسیرهای قدیمی `#/app/*` به مقصد مستقل متناظر هدایت می‌شوند.

کارت حساب و مسیر مستقیم از کنترل مشترک دسترسی استفاده می‌کنند. تغییر نشانی مجوز نمی‌سازد. API نوشتن، نشست معتبر، مبدأ امن، CSRF، پایان تست و دسترسی محصول را بررسی می‌کند؛ فقط ویرایش حساب و خروج به پایان تست یا مجوز محصول نیاز ندارند. انتخاب پلن و درخواست آزمایشی پس از پایان تست مجازند. انتخاب پلن به‌تنهایی دسترسی فعال ایجاد نمی‌کند. دادهٔ هویت و محیط کاری در پاسخ حساب بدون دسترسی فعال بازگردانده نمی‌شوند.

## مدل داده و مالکیت

همهٔ رکوردها با `owner_hash` به مالک نشست متصل‌اند. داده از سرویس فعلی Python و SQLite خوانده و ثبت می‌شود. تغییرات طرح صرفاً افزایشی‌اند:

| موجودیت | جدول | محتوای اصلی |
| --- | --- | --- |
| حساب | `pb_account_details` | `body` شامل name/email/phone/avatar، زمان تغییر |
| تنظیمات محصول | `pb_product_settings` | tone/format/length/selectedPlan و زمان تغییر |
| هویت | `pb_identity_records` و `pb_identity_versions` | اطلاعات حرفه‌ای، رضایت بینش تست، تأیید و تاریخچه |
| دسترسی | `pb_identity_access` | پلن، وضعیت، آزمایشی‌بودن |
| پیشنهاد AI | `pb_ai_outputs` | عملیات، ورودی، خروجی، وضعیت و زمان |
| مرجع صدا و ستون‌ها | `pb_brand_voice` و `pb_content_pillars` | خروجی پذیرفته‌شده و مبنای آن |
| محتوا و انتشار | `pb_content_items` | عنوان، متن، منشأ، وضعیت، metadata.publishAt |

هیچ جدول یا دادهٔ موجود برای این جداسازی حذف نمی‌شود. ثبت حساب، هویت و تنظیمات به یکدیگر وابسته نیستند. تصویر حساب فقط دادهٔ PNG/JPEG با سقف کوچک است؛ URL خارجی و SVG پذیرفته نمی‌شود. دادهٔ هویت پیشین، در صورت وجود و نداشتن نسخهٔ ثبت‌شده، تنها با پاسخ موفق سرویس وارد حساب می‌شود؛ منبع قبلی پاک نمی‌شود.

## قرارداد API

`GET /api/brandyar` پاسخ `{ok:true,data:{...}}` دارد. پاسخ بدون نشست فقط signedIn=false است. پاسخ معتبر شامل signedIn، csrf، demoAuth، account، access، testCompleted، trialUsed و aiReady است. برای دسترسی فعال identity، settings و workspace نیز بازگردانده می‌شوند.

workspace شامل brandVoice، contentPillars، library و recentOutputs است. هر مرجع دارای status/body/updatedAt است؛ هر محتوا needsRevision دارد. recentOutputs پنج پیشنهاد اخیر مالک را برای ادامهٔ بررسی بازمی‌گرداند.

`POST /api/brandyar` بدنهٔ JSON شامل csrf و action دریافت می‌کند:

| action | ورودی افزوده | خروجی data |
| --- | --- | --- |
| account_save | account:{name,email,phone,avatar?} | account |
| account_logout | — | signedIn:false |
| plan_select | planId:starter یا growth | access |
| trial_grant | planId | snapshot |
| access_revoke | — | access |
| identity_save | identity، sections?، insightApproval? | snapshot |
| identity_approve | approvedAt? | snapshot |
| settings_save | settings:{tone,format,length} | settings |
| publication_save | itemId، status، publishAt | workspace |
| ai_generate | operation، inputs | ai |
| ai_output_action | outputId، outputAction، edited? | ai، workspace |
| ai_feedback | outputId، rating، note? | feedbackSaved |
| library_action | itemId، libraryAction، title?، body? | library، workspace |

خطاها `{error:"متن قابل‌نمایش"}` هستند. 401 برای نشست، 403 برای مجوز/CSRF/پیش‌نیاز دسترسی، 422 برای ورودی نامعتبر و 503 برای سرویس در دسترس‌نبوده است. رابط فقط بعد از پاسخ موفق وضعیت ثبت‌شده نشان می‌دهد؛ خطا امکان تلاش دوباره را حفظ می‌کند.

publishAt تاریخ ISO است؛ وضعیت‌ها draft/ready/scheduled/published هستند. scheduled بدون تاریخ معتبر پذیرفته نمی‌شود. منتشرشده صرفاً اعلام دستی کاربر است؛ هیچ شبکهٔ اجتماعی از این مسیر فراخوانی نمی‌شود.

## مسیر و اعتبار خروجی

هفت مرحله: پایه، مخاطب، پیام و جایگاه، صدا، ستون‌ها، محتوا و انتشار. وضعیت‌ها از snapshot واقعی محاسبه می‌شوند، نه درصد نمایشی یا رکورد نمونه. نیازها و تفاوت‌ها ورودی تکمیلی‌اند؛ نبود آن‌ها به‌تنهایی تأیید هویت سازگار با قرارداد موجود را مسدود نمی‌کند.

صدای برند به نسخهٔ تأییدشدهٔ هویت وابسته است. ستون‌ها علاوه بر هویت، امضای محتوایی صدای تأییدشده را نگه می‌دارند. محتوا نیز امضای صدا و ستون‌ها را ثبت می‌کند. تغییر مبنا، خروجی وابسته را نیازمند بازبینی می‌کند، بدون حذف آن. پیشنهاد قدیمی یا تعیین‌تکلیف‌شده دوباره پذیرفته نمی‌شود. فرادادهٔ مبنا از فرم ویرایش قابل تغییر نیست. محتوای نیازمند بازبینی آمادهٔ انتشار ثبت نمی‌شود. مرحلهٔ وابسته آماده نشان داده نمی‌شود، ولی خروجی موجود برای بررسی قابل دسترسی می‌ماند.

## حدود واقعی و پذیرش

- هویت مالک همچنان نشست تست است؛ حساب دائمی مستقل، بازیابی میان دستگاه‌ها، تأیید تماس، تغییر رمز و مدیریت چند نشست فراهم نشده‌اند.
- پرداخت واقعی، ارسال خودکار و تضمین مدت/سهمیهٔ اشتراک ارائه نشده‌اند؛ دسترسی آزمایشی صریحاً جداست.
- آمادگی AI از پیکربندی سرویس خوانده می‌شود. آزمون معماری جایگزین آزمون اتصال زنده و هزینه‌دار نیست.
- آزمون‌های Python از دیتابیس و HTTP موقت با پاک‌سازی استفاده می‌کنند؛ Node VM قرارداد مسیر، جداسازی حساب و پیش‌نیازها را بررسی می‌کند.
- پذیرش بصری واقعی موبایل/دسکتاپ و اتصال زندهٔ AI در این مرحله انجام نشده‌اند. کنترل تاریخ ورودی بومی است؛ نمایش تاریخ‌های ثبت‌شده فارسی است.
