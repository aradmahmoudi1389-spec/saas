# برنامهٔ اعتبارسنجی و تضمین کیفیت

## قابلیت آماری واقعی

پنل، تعداد پاسخ هر مرحله و میانگین زمان ثبت آن را می‌خواند. زمان تمرکز گویه در مرورگر، در focus/select جمع می‌شود و هنگام خروج از focus یا مخفی‌شدن صفحه متوقف می‌شود. این زمانِ تفکر نیست، میان دستگاه‌ها دقیقاً قابل مقایسه نیست و امکان تقلب/اختلال ساعت مرورگر دارد.

برای هر نسخهٔ تست، حداکثر ۵۰۰۰ مجموعه پاسخ کامل مرحلهٔ سوم جداگانه تحلیل می‌شوند. هم‌بستگی Pearson میان گویه‌های یک بُعد و آلفای کرونباخ برای همان سه گویه محاسبه می‌شود. کمتر از پنج پاسخ فقط تعداد نمایش داده می‌شود؛ پنج، حد محاسباتی است نه اندازهٔ نمونهٔ پژوهشی کافی. واریانس صفر مقدار null می‌دهد، نه صفر ساختگی یا عدد نامتناهی. آلفای منفی حذف یا زیبا‌سازی نمی‌شود. پاسخ یکسان به همهٔ گویه‌ها صرفاً یک پرچم توصیفی است، نه مدرک بی‌اعتباری پاسخ‌دهنده.

خروجی مجاز پژوهشی فقط شامل نسخهٔ تست و پاسخ‌های عددی ۱۸ گویه است؛ شناسهٔ فرد/نشست/ارزیابی، زمان، متن آزاد، لینک و پیج ندارد. export ثبت حسابرسی دارد و برای analyst مجاز نیست. این خروجی تضمین ریاضی ناشناس‌بودن در ترکیب با همهٔ داده‌های بیرونی نیست؛ کنترل دسترسی و قرارداد استفادهٔ پژوهشی همچنان لازم است.

## محدودیت‌های اندازه‌گیری فعلی

مرحلهٔ سوم همهٔ گویه‌ها را الزامی ذخیره می‌کند؛ بنابراین پاسخ‌های جزئی در DB ثبت نمی‌شوند. نرخ پرش/تکمیل مستقل هر گویه، پاسخ رهاشده قبل از ذخیرهٔ مرحله و نرخ عدم پاسخ یک سؤال قابل محاسبهٔ معتبر نیستند و در UI جعل نشده‌اند. زمان‌ها فعلاً در آمار کلی گویه تجمیع می‌شوند؛ برای تفسیر تغییر متن، export و تحلیل باید به نسخهٔ سؤال محدود شوند.

بازخورد خبره در هر نسخه با مدیر ثبت‌کننده نگهداری می‌شود؛ workflow داوری چندخبره و taxonomy برچسب‌های پژوهشی پیاده نشده است. ویرایش گویه و وزن نسخهٔ مستقل می‌سازد؛ metadata کاربرد، جمعیت، محدودیت و not_validated همراه قالب اولیه ثبت است. تغییر جمعیت هدف یا اعلام validated از پنل فعلی مجاز/پیاده نیست.

## برنامهٔ پژوهش پیش از ادعای علمی

۱. ماتریس تعریف سازه/گویه، بررسی حقوق منابع و مصاحبهٔ شناختی فارسی با گروه هدف ثبت شود.
۲. خبرگان مستقل ارتباط، وضوح و تک‌مفهومی‌بودن گویه‌ها را ارزیابی کنند؛ نمونه، روش و تصمیم اصلاح ثبت شود.
۳. نمونه‌گیری با رضایت پژوهشی مستقل و برنامهٔ تحلیل ازپیش‌ثبت‌شده انجام شود؛ اندازهٔ نمونه با تحلیل توان و ساختار مدل انتخاب شود، نه حد محاسباتی پنج نفر.
۴. پایایی درونی، بازآزمایی، ساختار عاملی، روایی همگرا/افتراقی و ناوردایی گروه‌های مناسب بررسی شوند؛ از ویژگی حساس استنتاج‌شده استفاده نشود.
۵. cutoff بلوغ، وزن منابع و ارتباط توصیه‌ها با پیامد واقعی بازبینی شوند؛ هم‌بستگی به معنی علیت نیست.
۶. نسخهٔ اصلاحی مستقل منتشر شود؛ نتایج قبلی حفظ و مقایسه با هشدار تغییر نسخه انجام شود.
۷. فقط با گزارش واقعی، بازبینی پژوهشی و محدودیت‌های منتشرشده وضعیت اعتبارسنجی تغییر کند.

## آزمون خودکار

```sh
python3 -m pip install -r requirements-personal-brand.txt
python3 -m unittest discover -s . -p 'test_*.py'
node test_assessment.cjs
node test_admin_workspace.cjs
node test_personal_brand.cjs
node --check personal-brand.js
```

آزمون Python از SQLite موقت، سرویس HTTP موقت loopback و پاسخ‌های mock مشخص Meta استفاده می‌کند؛ اتصال زنده یا دادهٔ واقعی کاربر لازم ندارد. سرویس موقت در cleanup خاموش و thread جمع می‌شود. Node VM شبیه‌ساز قرارداد DOM است، نه مرورگر و نه تأیید بصری.

پوشش: حدود نمره و وزن، بلوغ، confidence، اعتبارسنجی، نسخهٔ immutable، reanalysis با مدل جدید، مالکیت/IDOR، csrf و origin، نقش مدیر/تحلیل‌گر، rate-limit، report retry، حذف cascade، rollback خالی و محافظ داده، OAuth state غلط/منقضی/تکراری/مالک دیگر، لغو، انقضای توکن، رد حساب شخصی، عدم نشت توکن، sync ناموفق با حفظ snapshot، قطع اتصال هم‌زمان grant، آمار دادهٔ ثابت و گزارش export.

UI contract: empty/error، معرفی فقط پس از رد اتصال، مسیر skip تا گزارش، escaping متن، لغو dialog بدون تأیید کهنه و مخفی‌بودن عملیات غیرمجاز. رگرسیون ارزیابی قدیمی و پنل قدیمی نیز اجرا می‌شود.

## پذیرش عملیاتیِ انجام‌نشده

تست بصری/مرورگری و E2E مرورگری در این محیط اجرا نشده‌اند. قبل از انتشار عمومی، تیم محصول باید روی دستگاه واقعی، keyboard/screen reader، موبایل، بازگشت OAuth رسمی، حساب شخصی و حرفه‌ای، اختلال شبکه، حذف backup، callback در reverse proxy و بازیابی backup را بررسی کند. OAuth mock و syntax-check جایگزین این پذیرش نیستند.
