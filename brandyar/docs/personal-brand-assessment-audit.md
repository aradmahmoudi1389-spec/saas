# ممیزی ارزیابی پرسونال برند

## وضعیت پیش از تغییر

پروژه HTML/CSS/JavaScript استاتیک و Python ThreadingHTTPServer است. `server.py` مالک route، cookie، SQLite و اتصال سروری Supabase است. `brand_analysis.py` فقط پاسخ‌های انتخابی نسخهٔ ثابت `assessment_questions.json` را برای تولید گزارش با schema قدیمی می‌فرستد. گزارش قدیمی در Supabase assessments و تاریخچهٔ مدیریتی در SQLite نگهداری می‌شود. مسیرهای قدیمی `/api/assessment/*` و hash-routeهای عمومی حفظ می‌شوند.

احراز هویت staff با scrypt، نشست HttpOnly و TOTP است. حساب عمومی پایدار برای آزمون وجود ندارد؛ ارزیابی قدیمی از نشست کوتاه‌مدت استفاده می‌کند. دارایی بصری موجود، فونت وزیر و پالت سبز پنل حفظ می‌شوند. رسانه در این ماژول آپلود نمی‌شود. اتصال Instagram، consent، مدل شش‌بعدی یا موتور نمره‌دهی شفاف پیش از این وجود نداشت. اسناد پنل مدیریت قبلی توصیف این قابلیت جدید محسوب نمی‌شوند.

## معماری پیشنهادی و migration

ماژول جدید مستقل و افزایشی در `/personal-brand`، APIهای `/api/personal-brand`، callback رسمی Instagram و صفحهٔ مدیریتی مستقل ساخته می‌شود تا قرارداد گزارش قدیمی نشکند. SQLite کنونی با پیشوند `pb_` گسترش می‌یابد؛ هیچ جدول فعلی تغییر نام یا حذف نمی‌شود. هویت عمومی فعلاً نشست ناشناس HttpOnly با عمر محدود است، نه حساب ثبت‌نام‌شده یا ایمیل تأییدشده. مالکیت همهٔ رکوردها به hash همین نشست محدود می‌شود. بازیابی بین دستگاه‌ها بدون احراز هویت عمومی ممکن نیست و در UI صریح گفته می‌شود.

قالب سؤال و مدل نمره‌دهی snapshot مستقل و immutable دارند. تولید گزارش قطعی و شفاف با محاسبات نسخه‌دار انجام می‌شود؛ ادعای تحلیل تصویری یا نتیجهٔ AI بدون provider مجاز وجود ندارد. دادهٔ رسمی پیج لایهٔ مشاهده و مقایسهٔ شواهد است، نه جایگزین پاسخ‌ها. متن واردشده هرگز HTML اجرا نمی‌کند.

## ریسک و مرزها

هیچ secret در مرورگر یا لاگ چاپ نمی‌شود. اتصال Instagram نیازمند اپ Meta، callback HTTPS، تنظیمات محیطی و کتابخانهٔ رمزنگاری استاندارد است. نبود هر وابستگی باید اتصال را واقعاً غیرفعال کند؛ مسیر بدون اتصال کامل باقی می‌ماند. state یک‌بارمصرف به نشست و رضایت مرتبط است. دسترسی مدیر جدا از کاربر و توکن هرگز در پاسخ مدیریتی هم نیست. لینک شواهد فقط ثبت می‌شود و به‌صورت خودکار fetch نمی‌شود. هیچ scraping، تحلیل چهره، تشخیص شخصیت یا ویژگی حساس انجام نمی‌شود.

## برنامهٔ اجرا

۱. migration افزایشی، چارچوب شش‌بعدی و اعتبارسنجی.
۲. API واقعی شروع، ذخیرهٔ مراحل، گزارش نسخه‌دار، مالکیت، حذف و audit.
۳. OAuth رسمی، snapshot و مدیریت قطع/حذف و خطای همگام‌سازی با mock در تست.
۴. رابط پنج‌مرحله‌ای، نتیجه و مدیریت نسخه‌ها.
۵. تست HTTP بدون مرورگر و اسناد عملیاتی.

وضعیت واقعی اجرا و وابستگی‌های بیرونی در اسناد معماری، setup و validation همراه ماژول ثبت می‌شود. استقرار و migration زنده در این درخواست انجام نمی‌شود؛ تغییر کد محلی به معنای انتشار نیست.

## نتیجهٔ ممیزی پس از پیاده‌سازی

### قابلیت‌های واقعی

- مسیر مستقل کاربر و مدیریت و پیوند ورودی از سایت/پنل موجود، بدون حذف مسیر قدیمی.
- پنج مرحلهٔ فارسی، ۱۸ گویهٔ شش‌بُعدی، ترتیب تصادفی ثابت، اعتبارسنجی، draft محلی و ذخیرهٔ قطعی سرور.
- نمرهٔ شفاف، مرحله و الگوی احتمالی، وزن منبع آشکار، توصیهٔ مبتنی بر گویه و گزارش HTML قابل دریافت.
- migration افزایشی و FK، ورودی و گزارش نسخه‌دار، کنترل UPDATE نسخهٔ منتشرشده، بازتحلیل با مدل جدید و دلیل، مقایسهٔ نتایج و آرشیو نرم.
- مالکیت داده، CSRF/HTTPS، نقش private برای جزئیات، محدودیت درخواست، escape خروجی، audit و export عددی محدودشده.
- OAuth رسمی با رضایت نسخه‌دار و state امن؛ رمزنگاری استاندارد توکن، اعتبارسنجی حساب و هویت، دریافت allowlist فیلدها و عدم انتشار پاسخ خام سرویس.
- sync متنی/فراداده، حفظ آخرین دادهٔ موفق در خطا، انقضا، قطع اتصال، حذف واقعی cascade و حذف دادهٔ مشتق‌شده.
- سیاست snapshot با retention قابل تنظیم، پاک‌سازی هنگام درخواست و ابزار مستقل cleanup/rollback محافظت‌شده.
- فیلتر و صفحه‌بندی مدیریتی، نسخه‌های سؤال/وزن، خطاهای sync، بازخورد خبره و آمار توصیفی مقدماتی جدا برای هر نسخه.

### نتیجهٔ آزمون

۱۳۵ آزمون Python برای کل پروژه، شامل ۳۵ اجرای تست ماژول جدید، و سه مجموعهٔ Node برای پنل قبلی، ارزیابی قبلی و ماژول جدید موفق شدند. برخی تست‌های storage در کلاس OAuth نیز برای fixture رمزنگاری تکرار می‌شوند؛ تعداد اجرا با تعداد سناریوهای مستقل پژوهشی یکسان نیست. syntax جاوااسکریپت و whitespace diff نیز بررسی شدند. تست‌ها فقط DB موقت دارند و سرویس HTTP موقت را می‌بندند. تست مرورگری/بصری و Meta زنده انجام نشده است.

### موارد بیرونی و راه‌اندازی

اپ واقعی Meta، app review/سطح مجوز لازم، dependency روی سرور، secretهای محیطی، callback HTTPS هم‌دامنه، حذف query از logِ proxy، برنامهٔ نگهداری دوره‌ای و نسخهٔ پشتیبان/بازیابی لازم‌اند. هیچ‌کدام با ساخت کد، نصب یا تأییدشده محسوب نمی‌شوند. قرارداد زندهٔ فیلدها/نسخهٔ Graph باید با اپ واقعی تطبیق داده شود. DB تولید و Supabase در این اجرا تغییر نکرده‌اند.

### فاصلهٔ واقعی تا تمام معیارهای سند اولیه

۱. تحلیل معنایی لحن، موضوع و شکاف هویت/محتوا، تحلیل تصویر/ویدیو، insights، کامنت و refresh توکن پیاده نشده‌اند؛ موتور فعلی rule-based و محدود به خوداظهاری و شاخص‌های لغوی/فراداده است. برچسب «تحلیل کامل» صادر نمی‌شود.
۲. حساب عمومی دائمی، recovery بین دستگاه‌ها و جست‌وجوی نام/ایمیل کاربر وجود ندارد؛ مالکیت نشست شفاف است.
۳. پنل سؤال‌ها فعلاً متن گویه و نسخه را مدیریت می‌کند؛ نوع پاسخ/بُعد/تعداد/وزن مستقل گویه و rule-builder شرطی ثابت‌اند. الگوی روایت‌گر و الگوهای فرعی موتور مستقل ندارند.
۴. نرخ پرش و زمان دقیق تفکر هر سؤال، workflow داوری چندخبره و اعتبار علمی کامل وجود ندارند. آمار توصیفی جایگزین پژوهش نیست.
۵. callback امضاشدهٔ حذف Meta، برنامهٔ حقوقی حذف backup و retention عمومی audit/پرسش‌نامه باید پیش از انتشار عمومی نهایی شوند؛ ابزار حذف درون محصول واقعی است، اما این امور بیرونی خودکار تنظیم نشده‌اند.
۶. آزمون E2E مرورگری و پذیرش بصری واقعی اجرا نشده‌اند. فقط پوشش HTTP و Node VM موجود است.

بنابراین هستهٔ عملیاتی و مسیر بدون اتصال تحویل شده‌اند، اما کل دامنهٔ تحلیل پیشرفتهٔ سند اولیه کامل اعلام نمی‌شود. فهرست محدودیت‌ها در UI و اسناد پنهان نشده است.
