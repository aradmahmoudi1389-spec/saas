# تحلیل رویداد و قیف پنل نشارو

## رویدادهای ثبت‌شده

از مسیر واقعی تحلیل این eventها ثبت می‌شوند:

- `analysis_started`
- `analysis_ready`
- `analysis_failed`
- `assessment_stored`
- `lead_registered`

برای event شناسهٔ ارزیابی، نسخهٔ تست فعلی، نسخهٔ پرامپت در صورت وجود و زمان ثبت می‌شود. شمارش‌ها با بازهٔ زمانی exact از SQLite و Supabase خوانده می‌شوند.

## داشبورد

`overview` و `reports` تعداد واقعی lead، assessment، تکمیل‌شده، وظایف overdue و eventها را برمی‌گردانند. بازه‌های ۱، ۷، ۳۰ روز و custom تا ۳۶۶ روز پشتیبانی می‌شود. دادهٔ فاقد منبع صفر یا empty نمایش داده می‌شود؛ نرخ تبدیل یا کاربر یکتا ساخته نمی‌شود.

## رویدادهای فاقد منبع

بازدید گزارش، شروع/تکمیل ثبت‌نام عمومی، شروع خرید، پرداخت، لغو پرداخت، فعال‌سازی و تغییر پلن در معماری فعلی منبع معتبر و سفارش واقعی ندارند. این eventها و funnel کامل تا اتصال منبع واقعی فعال نشده‌اند.

## backfill

هیچ backfill تخمینی انجام نشده است. eventهای این migration از زمان ثبت نسخهٔ جدید محاسبه می‌شوند. eventهای قبلی که در جدول معتبر موجود نیستند به گذشته نسبت داده نمی‌شوند.

## idempotency و توسعهٔ بعدی

ثبت eventهای فعلی از شناسهٔ assessment و UUID event استفاده می‌کند. برای funnel تجاری بعدی باید جدول event با کلید idempotency، source، path، session و order تعریف شود و event پرداخت فقط از backend پرداخت معتبر شود؛ تا آن زمان UI باید وضعیت «اتصال موجود نیست» را نشان دهد.
