# راه‌اندازی اتصال رسمی اینستاگرام

## وضعیت تحویل

کد اتصال و تست‌های mock آماده‌اند؛ اتصال زنده، مجوز یک حساب واقعی و تأیید اپ Meta در این اجرا انجام نشده‌اند. تلاش برای خواندن مستند رسمی جاری از این محیط موفق نبود؛ پیش از فعال‌سازی، اپراتور باید قرارداد endpoint/field/permission را با نسخهٔ Graph انتخاب‌شده در داشبورد Meta تطبیق دهد. پاسخ موفق mock به معنی تأیید سرویس زنده نیست.

بدون dependency یا هر یک از تنظیمات ضروری، اتصال واقعاً غیرفعال می‌شود. ارزیابی بدون اتصال همچنان کامل قابل انجام است.

## متغیرهای محیطی ضروری، بدون مقدار

- `META_INSTAGRAM_APP_ID`
- `META_INSTAGRAM_APP_SECRET`
- `META_INSTAGRAM_REDIRECT_URI`
- `META_GRAPH_VERSION`
- `PB_TOKEN_ENCRYPTION_KEY`

نسخهٔ Graph باید قالب `vN.N` و نسخهٔ پشتیبانی‌شدهٔ اپ باشد. کلید Fernet باید توسط مدیر امن زیرساخت تولید و در مدیریت secret سرویس نگهداری شود؛ آن را در گیت، خروجی ترمینال عمومی، چت، screenshot یا مرورگر قرار ندهید. تعویض کلید بدون فرایند بازرمزنگاری، اتصال‌های فعلی را غیرقابل استفاده می‌کند و نیازمند اتصال مجدد است.

## پیکربندی Meta

۱. برای مالک محصول در Meta Developers یک اپ با محصول Instagram و مسیر Instagram Login ایجاد کنید؛ این پیاده‌سازی Facebook Login نیست.
۲. محیط توسعه و تولید را جدا کنید؛ شناسهٔ اپ، secret، کلید رمزنگاری و DB هر محیط مستقل باشند.
۳. redirect URI دقیق، HTTPS و روی همان دامنهٔ نشست باشد. مسیر ضروری `/api/personal-brand/instagram/callback` است. query، fragment، userinfo یا redirect میانی مجاز نیست. callback باید در allowlist اپ عیناً ثبت شود.
۴. صفحهٔ سیاست حریم خصوصی، راهنمای حذف داده، اطلاعات تماس و مالکیت دامنهٔ واقعی محصول را در تنظیمات اپ تکمیل کنید. این تحویل callback امضاشدهٔ حذف خودکار Meta را پیاده نکرده است؛ از گزینهٔ دستورالعمل حذف داده فقط در صورتی استفاده کنید که داشبورد اپ آن را قبول کند، وگرنه قبل از انتشار callback لازم باید اضافه شود.
۵. در development فقط حساب‌ها/افراد آزمایشی مجاز اپ را با نقش مناسب اضافه کنید. Business یا Creator لازم است؛ حساب شخصی پشتیبانی نمی‌شود و هیچ رمز اینستاگرامی در محصول گرفته نمی‌شود.
۶. مجوز `instagram_business_basic` برای خواندن پروفایل و رسانهٔ متعلق به همان حساب درخواست می‌شود. insights، انتشار محتوا، پیام و کامنت جزو این پیاده‌سازی نیستند و درخواست نمی‌شوند.
۷. برای دسترسی کاربران بیرون از نقش‌های آزمایشی، مطابق الزامات جاری Meta، بررسی اپ، سطح دسترسی لازم، احراز کسب‌وکار در صورت مطالبه و توضیح کاربرد/ویدئوی بررسی را تکمیل کنید. صرف Live کردن اپ جای تأیید مجوز را نمی‌گیرد.
۸. پس از نصب dependency و تنظیم environment سرویس، OAuth واقعی، رد مجوز، callback، bio، رسانه، انقضا و قطع اتصال را با حساب تحت اختیار محصول آزمایش کنید.

## جریان پیاده‌شده

مجوز در `www.instagram.com/oauth/authorize` درخواست می‌شود؛ کد در سرور با `api.instagram.com/oauth/access_token` مبادله می‌شود. پروفایل و media از `graph.instagram.com` و نسخهٔ تنظیم‌شده خوانده می‌شوند. توکن در query مرورگر یا پاسخ API محصول قرار نمی‌گیرد؛ درخواست Graph از Authorization header استفاده می‌کند.

state تصادفی، فقط به صورت hash، ده دقیقه معتبر، یک‌بارمصرف و متعلق به نشست و consent است. لغو یا قطع اتصال در حین پاسخ سرویس، grant در حال اجرا را نامعتبر می‌کند. callback به یک مسیر ثابت داخلی با وضعیت محدود connected/failed/cancelled برمی‌گردد؛ redirect دلخواه پذیرفته نیست.

## فیلدها و محدودیت‌ها

شناسه، username و account_type برای احراز حساب حرفه‌ای خوانده می‌شوند. biography، name و website جداگانه و best-effort درخواست می‌شوند؛ نبودن هر کدام در `unavailable_fields` ثبت می‌شود و مقدار ساختگی جای آن نمی‌آید. media شامل id، caption، media_type، timestamp و permalink است؛ حداکثر ۲۵ مورد، بدون pagination یا دانلود رسانه. دسترسی دقیق این فیلدها باید پیش از انتشار با اپ واقعی تأیید شود.

## انقضا و خطا

توکن اولیه کوتاه‌عمر است؛ expires_in معتبر استفاده می‌شود و در نبود آن عمر محافظه‌کارانهٔ یک ساعت اعمال می‌شود. long-lived exchange، refresh و تمدید خودکار در این نسخه وجود ندارند. پس از انقضا، توکن غیرقابل استفاده می‌شود و UI اتصال دوباره را پیشنهاد می‌کند. خطای sync آخرین snapshot موفق را تا زمان retention نگه می‌دارد و خطای امن ثبت می‌کند؛ پاسخ خام سرویس وارد API یا log محصول نمی‌شود.

## ملاحظات سرور

- TLS و reverse proxy مورداعتماد لازم‌اند؛ هدرهای Forwarded/Real-IP باید بازنویسی شوند.
- access log مربوط به callback باید query string را ذخیره نکند؛ logging فقط path و status باشد. کد برنامه log درخواست HTTP را چاپ نمی‌کند، اما nginx/CDN مستقل‌اند و این تنظیم هنوز روی سرور انجام نشده است.
- DB و کلید رمزنگاری جدا، backup رمزنگاری‌شده و دسترسی محدود داشته باشند.
- پاک‌سازی دوره‌ای حداقل روزانه با ابزار maintenance روی سرور تنظیم شود.
- disconnect استفادهٔ آینده از مجوز محلی را متوقف می‌کند؛ revoke از سمت پلتفرم از تنظیمات رسمی Instagram/Meta نیز ممکن است. revoke سروری از طریق Meta در این نسخه فراخوانی نمی‌شود.
